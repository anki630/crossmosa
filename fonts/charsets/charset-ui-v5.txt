# charset-ui-v5.txt -- UI builtin-font character set (CrossMosa v112)
#
# !!! ASCII-ONLY HEADER !!!  This whole file is fed to pyftsubset via --text-file,
# so EVERY character in it (header included) becomes part of the font subset.
# Printable ASCII is already in the set, so an ASCII header costs nothing.
# NEVER put CJK or CJK punctuation in this header: it would silently enter the
# font.  regen-v112.sh asserts the resulting cmap, which is what catches it.
#
# LINEAGE
#   charset-ui-v4.txt (5,683 cp / 5,413 Han: BIG5 Level 1 + library-specific extras)
#   + 2,000 Han added by v112  =  7,683 cp / 7,413 Han
#   v4 content is reproduced VERBATIM below, then the 2,000 new chars sorted by
#   codepoint, so `diff charset-ui-v4.txt charset-ui-v5.txt` is a pure addition.
#
# WHY
#   v4's Han coverage is BIG5 Level 1 plus 357 chars harvested from ONE library
#   (the maintainer's).  Other people's libraries hit tofu on BIG5 Level 2 chars:
#   given-name characters, place names, variant forms.  v112 is the public-1.0
#   quality bar -- cover the useful half of BIG5 Level 2 as well.
#
# CANDIDATE POOL  (retrieved 2026-08-07)
#   [A] MOE standard character lists, Republic of China (Taiwan), 1982 --
#         "chang yong guo zi biao"     (Level 1 standard forms) 4,808 chars
#         "ci chang yong guo zi biao"  (Level 2 standard forms) 6,343 chars
#       Retrieved from https://github.com/zispace/hanzi-chars
#       @ 105544909cab18db1fedfd41a42c87408fbaac59 (2026-04-05), directory
#       data-charlist/ (the two 1982 Taiwan files).  That repo cites
#       language.moe.gov.tw, ButTaiwan/cjktables and zh.wikisource.org.
#   [B] Characters with corpus frequency >= 200 that are in NEITHER MOE list --
#       variant and technical forms the 1982 lists do not classify, e.g.
#       U+88CF (variant of U+88E1), U+5E84 (variant of U+838A), U+5398.
#
# FREQUENCY SOURCE  (retrieved 2026-08-07)
#   Chih-Hao Tsai, "Frequency and Stroke Counts of Chinese Characters",
#   https://technology.chtsai.org/charfreq/   data file .../charfreq/sorted.zip
#   Frequency of all 13,060 BIG5 characters over a 171,882,493-character corpus
#   of Traditional-Chinese Usenet posts, 1993-1994 (counts by Shih-Kun Huang,
#   NCTU; 1993+1994 pooled by Tsai).  Published 1996-01-01, updated 2005-08-03.
#   This is the only public frequency table that ranks the whole of BIG5, i.e.
#   the only one that can rank Level-2 characters at all.  Its tail is weak:
#   below about rank 1,000 the counts are 15-50 out of 172M and the ordering is
#   near-arbitrary.  That is acceptable here because the pool is already
#   restricted to characters an official standard calls second-tier common.
#
# SELECTION RULE  (deterministic; re-runnable -- see fonts-src/regen-v112.sh)
#   candidates = (pool A union pool B)
#                minus codepoints already rendered by ubuntu_14_regular.h
#                minus codepoints absent from NotoSansTC-Regular OR -Bold
#                restricted to U+4E00..U+9FFF
#   sort by corpus frequency DESC, ties by codepoint ASC; take the first 2,000.
#
# RESULT
#   pool 5,739 -> 2,000 selected.  1,980 from the Level 2 list, 20 by rule B.
#   By BIG5 block: 1,999 Level 2, 1 ETen extension, 0 Level 1.
#   Frequency span: U+5565 (34,124 occurrences) .. U+784C (15).
#   Dropped for absence from NotoSansTC: 2 (U+53C4, U+5B0E).
#   These 2,000 carry 78.1% of all corpus occurrences of not-yet-covered Han,
#   and 86.5% of the occurrences inside the candidate pool.
#   HONEST CAVEAT ON THE CUT: 226 pool characters tie at frequency 15 and 110 of
#   them are taken, so the last ~110 slots are decided by codepoint order, not by
#   any linguistic signal.  That is deterministic and reproducible, not principled.
#   Anything at 15 occurrences per 172M is below the noise floor either way.
#
# KNOWN GAP (deliberate, not an oversight)
#   Pool and frequency table are both BIG5-scoped, so Han outside BIG5 stays
#   uncovered -- including popular non-BIG5 given-name characters such as
#   U+5586, U+5F63, U+5803.  Closing that needs a different, non-BIG5 source.
